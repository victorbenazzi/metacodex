# metacodex 1.0.0

O metacodex 1.0 é um workspace local-first reconstruído para quem programa com agentes de código em terminais reais. Projetos, sessões ao vivo, arquivos, source control e previews de implementação agora compartilham uma única superfície desktop nativa sem substituir as ferramentas de linha de comando em que você já confia.

[Read these notes in English](https://github.com/victorbenazzi/metacodex/blob/main/docs/releases/v1.0.0.md)

> [!WARNING]
> Os DMGs da versão 1.0.0 para macOS não foram notarizados pela Apple. O Gatekeeper pode bloquear o DMG antes da montagem. Veja as [instruções temporárias de instalação](#aviso-do-gatekeeper-no-macos) abaixo.

## Um workspace organizado em torno do trabalho ao vivo

A nova shell dá um lugar estável para cada tipo de trabalho:

- A sidebar esquerda reúne projetos, terminais ativos, agentes de código e histórico de sessões retomáveis.
- O centro permanece dedicado ao processo ativo, com branch, status e atualização por perto.
- O workbench direito mantém Changes, Files, editores, diffs e previews disponíveis sem remontar o terminal ativo.
- Atalhos conscientes de foco fecham e alternam a superfície que você realmente está usando.
- Ordem de projetos, estado expandido e documentos persistem por workspace.

Porcelain e Graphite substituem a antiga galeria de paletas por um sistema claro e escuro focado. Os dois temas usam os mesmos tokens semânticos no chrome, na sintaxe do editor e nas cores do terminal. A densidade pode ser compacta, confortável ou espaçosa sem quebrar o alinhamento.

## Agentes de código em terminais reais

O metacodex continua abrindo CLIs reais por meio de uma PTY real. A versão 1.0 torna esse runtime resiliente para sessões longas:

- A ordem preparar, anexar e iniciar impede que a saída chegue antes da UI.
- Um journal limitado e sem perdas pode reproduzir a saída depois de uma interrupção do frontend.
- Um único supervisor controla saída e limpeza, com motivos explícitos para encerramento normal, erro de leitura, kill e entrega travada.
- O estado por aba acompanha idle, working, needs-attention e done.
- Linhas de projeto resumem sessões ao vivo, e o command center pode saltar para o próximo agente que precisa de atenção.
- O histórico captura CLI, cwd, branch e portas em escuta para retomada rápida.
- O encerramento seguro espera editores, configurações, workspaces, histórico e recursos em segundo plano, oferecendo tentar novamente ou forçar saída quando necessário.
- Notificações e som podem chamar você de volta quando um agente termina.

O launcher inclui Metacodex CLI, Claude Code, Codex CLI, OpenCode, Kimi Code e outros agentes de terminal. As configurações de agentes habilitados continuam sendo a fonte de verdade de todas as superfícies de lançamento.

## Um browser feito para implementação

![Preview do projeto e contexto visual](https://raw.githubusercontent.com/victorbenazzi/metacodex/v1.0.0/docs/releases/assets/v1.0.0/browser-workflow.jpg)

O workbench direito agora inclui um browser nativo pensado para debugging:

- Abra servidores locais detectados ou caminhos absolutos do projeto.
- Navegue páginas HTTP e HTTPS em um perfil isolado.
- Selecione um elemento, desenhe uma anotação ou capture uma região precisa.
- Envie DOM e contexto visual direto para o agente de código ativo.
- Preserve caminhos locais em vez de convertê-los em URLs públicas.
- Abra URLs e arquivos autorizados no aplicativo padrão do sistema.
- Exiba erros de navegação, captura e abertura externa em vez de manter um loading falso.

As mensagens da bridge são autenticadas, limitadas em tamanho e conscientes do modo atual. Arquivos locais usam grants não forjáveis, e cada caminho continua passando pela fronteira de roots de projeto ou preview grants.

## Source control e workbench de arquivos

A coluna direita agora é um workbench completo de implementação:

- Changes com arquivos staged e unstaged.
- Adições e remoções inline, com proteção para diffs grandes.
- Ações de stage, unstage, descarte e commit.
- Criação, troca e merge de worktrees.
- Explorador mutável com criar, renomear, deletar e arrastar-mover.
- Editores de código, Markdown, imagem, PDF e diff.
- Escrita atômica e abas que acompanham renomeações.

## Linux e Windows

A versão 1.0 leva a mesma base para além da origem macOS-first:

- Linux usa WebKitGTK para snapshots nativos do browser.
- Windows usa WebView2 para snapshots nativos do browser.
- Coordenadas CSS de recorte são escaladas para o bitmap nativo antes da codificação PNG.
- Linux e Windows descobrem portas TCP em escuta pelas tabelas nativas de sockets.
- Arquivos externos do projeto abrem no aplicativo padrão depois da autorização do caminho.
- A instalação do Metacodex CLI agora usa uma sequência PowerShell válida no Windows.
- Árvores de processos PTY permanecem contidas por Job Objects no Windows.

Os artefatos cobrem macOS Apple Silicon, macOS Intel, Windows x64, Linux x64 `.deb` e Linux x64 `.rpm`.

## Confiabilidade e segurança

A shell Rust continua sendo a única dona do acesso ao sistema operacional. O frontend React renderiza estado e invoca comandos Tauri tipados.

- Todo comando de filesystem valida os roots registrados antes de acessar o disco.
- Travessia por symlink e tentativas com diretório pai falham de forma segura.
- Grants de preview e diretório surgem apenas depois de consentimento do usuário.
- Escritas usam um arquivo temporário irmão seguido de rename atômico.
- A saída PTY aplica backpressure limitado sem descartar sequências de terminal.
- Saves de workspace carregam revisions para impedir que escrita antiga substitua estado novo.
- A coordenação de saída evita perda silenciosa de estado pendente.
- Nomes de comandos e eventos IPC passam por checagem de paridade entre Rust e TypeScript.

## Aviso do Gatekeeper no macOS

A build do macOS usa a identidade própria do projeto. Ela não foi assinada com Apple Developer ID e não foi notarizada. Por isso, o Gatekeeper pode mostrar uma mensagem dizendo que a Apple não pôde verificar o arquivo antes da montagem do DMG. A Apple não revisou esta build, então continue somente se você fez o download por esta release oficial.

### Método recomendado

1. Clique duas vezes no DMG baixado uma vez e feche o aviso.
2. Abra **menu Apple > Ajustes do Sistema > Privacidade e Segurança**.
3. Role até **Segurança** e clique em **Abrir Mesmo Assim**. A Apple disponibiliza essa opção por aproximadamente uma hora após a tentativa bloqueada.
4. Confirme **Abrir** e arraste `metacodex.app` para `/Applications`.

Esse é o procedimento de exceção documentado pelo [Suporte da Apple](https://support.apple.com/pt-br/102445).

### Alternativa pelo Terminal

Confira o arquivo antes de remover a quarentena:

| Mac | Arquivo | SHA-256 esperado |
| --- | --- | --- |
| Apple Silicon | `metacodex_1.0.0_aarch64.dmg` | `859521bc39f023768c244d00cac9135a34eb42474715b7e15e328839819ff5f6` |
| Intel | `metacodex_1.0.0_x64.dmg` | `fdbd4154754d36859f72a5f024e7b498575f1bf52747a15a4e10d90e001b0fc4` |

```bash
shasum -a 256 "$HOME/Downloads/metacodex_1.0.0_aarch64.dmg"
xattr -d com.apple.quarantine "$HOME/Downloads/metacodex_1.0.0_aarch64.dmg"
open "$HOME/Downloads/metacodex_1.0.0_aarch64.dmg"
```

Quem usa Mac Intel deve substituir `aarch64` por `x64`. Se o Gatekeeper também bloquear o aplicativo depois da cópia, execute:

```bash
sudo xattr -dr com.apple.quarantine "/Applications/metacodex.app"
open "/Applications/metacodex.app"
```

Esses comandos removem a quarentena somente do arquivo especificado do metacodex. Eles não desativam o Gatekeeper no sistema. Uma versão futura assinada com Apple Developer ID e notarizada pela Apple eliminará essa etapa adicional.

## Atualizando a partir da 0.0.19

O app mantém a identidade `com.metacodex.app` e a raiz `~/.metacodex`, então projetos, configurações, atalhos e estado de workspace continuam disponíveis. A compatibilidade de startup arquiva o estado da Agent view e do experimento SSH removidos em `state/legacy-agent/` e `state/legacy-ssh/`.

O produto anterior continua disponível como [Legacy v0.0.19](https://github.com/victorbenazzi/metacodex/releases/tag/v0.0.19), com o código congelado na branch [`legacy/v0`](https://github.com/victorbenazzi/metacodex/tree/legacy/v0).
