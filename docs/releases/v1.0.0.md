# metacodex 1.0.0

metacodex 1.0 is a rebuilt local-first workspace for developers who work with coding agents in real terminals. Projects, live sessions, files, source control and implementation previews now share one native desktop surface without replacing the command-line tools you already trust.

## A workspace organized around live work

The new shell gives each kind of work a stable place:

- The left sidebar holds projects, running terminals, coding agents and resumable session history.
- The center stays dedicated to the active process, with branch, status and update context close at hand.
- The right workbench keeps Changes, Files, editors, diffs and project previews available without remounting the active terminal.
- Focus-aware shortcuts close and cycle the surface you are actually using.
- Project order, expanded state and document tabs persist per workspace.

Porcelain and Graphite replace the old palette gallery with one focused light and dark system. Both themes use the same semantic tokens across chrome, editor syntax and terminal colors. UI density can be compact, comfortable or spacious without breaking alignment.

## Terminal-native coding agents

metacodex continues to launch real CLIs through a real PTY. Version 1.0 makes that runtime resilient enough for long sessions:

- Prepare, attach and start ordering prevents output from racing ahead of the UI.
- A bounded, lossless event journal can replay output after frontend interruption.
- A single supervisor owns process exit and cleanup, with explicit reasons for normal exit, reader failure, kill and stalled delivery.
- Agent state tracks idle, working, needs-attention and done per tab.
- Project rows summarize live sessions, and the command center can jump to the next agent that needs attention.
- Session history captures CLI, cwd, branch and listening ports for quick resume.
- Safe quit waits for editors, settings, workspaces, history and background resources, then offers retry or explicit force quit if necessary.
- OS notifications and sound can bring you back when an agent finishes.

The launcher includes Metacodex CLI, Claude Code, Codex CLI, OpenCode, Kimi Code and other terminal agents. Enabled-agent settings remain the source of truth for every launcher surface.

## A browser made for implementation

![Project preview and visual context](https://raw.githubusercontent.com/victorbenazzi/metacodex/v1.0.0/docs/releases/assets/v1.0.0/browser-workflow.jpg)

The right workbench now includes a native project browser designed for debugging work:

- Open detected local development servers or absolute project files.
- Navigate regular HTTP and HTTPS pages inside an isolated browser profile.
- Pick an element, draw an annotation or capture a precise region.
- Send the selected DOM and visual context directly to the active coding agent.
- Keep local file paths intact instead of converting them into public URLs.
- Open authorized URLs and project files with the operating system default application.
- Surface navigation, capture and external opener errors instead of leaving the browser in a false loading state.

Browser bridge messages are authenticated, size-bounded and mode-aware. Local files are served through unforgeable grants, and every path still passes through the project-root or preview-grant boundary.

## Source control and file workbench

The right column is now a complete implementation workbench:

- Changes view with staged and unstaged files.
- Inline additions and removals with large-diff safeguards.
- Stage, unstage, discard and commit actions.
- Worktree creation, switching and merge workflows.
- Mutable file explorer with create, rename, delete and drag-move.
- Editors for source, Markdown, images, PDF and diffs.
- Atomic file writes and rename-aware open tabs.

## Linux and Windows

Version 1.0 moves the shared codebase beyond its original macOS-first boundary:

- Linux uses WebKitGTK for native browser snapshots.
- Windows uses WebView2 for native browser snapshots.
- CSS crop coordinates are scaled to the native bitmap before PNG encoding.
- Linux and Windows discover listening TCP ports from their native socket tables.
- External project files open through the platform default application after path authorization.
- The Metacodex CLI install command now uses valid PowerShell sequencing on Windows.
- PTY process trees remain contained on Windows through Job Objects.

Release artifacts target macOS Apple Silicon, macOS Intel, Windows x64, Linux x64 `.deb` and Linux x64 `.rpm`.

## Reliability and security

The Rust shell remains the only owner of operating-system access. The React frontend renders state and invokes typed Tauri commands.

- Every filesystem command checks registered project roots before touching disk.
- Symlink traversal and parent-directory escape attempts fail closed.
- Preview and directory grants are created only behind user consent boundaries.
- File writes use a temporary sibling and atomic rename.
- PTY output uses bounded backpressure without dropping stateful terminal sequences.
- Workspace saves carry revisions so stale writes cannot overwrite newer state.
- Quit coordination prevents silent loss of pending state.
- IPC command and event names are checked for Rust and TypeScript parity.

## macOS Gatekeeper notice

The macOS build uses the project's self-signed identity. It is not signed with an Apple Developer ID and is not notarized. Gatekeeper can therefore show an "Apple could not verify" message before the DMG mounts. Apple has not reviewed this build, so continue only if you downloaded it from this official release.

### Recommended method

1. Double-click the downloaded DMG once and dismiss the warning.
2. Open **Apple menu > System Settings > Privacy & Security**.
3. Scroll to **Security** and click **Open Anyway**. Apple makes this option available for about one hour after the blocked attempt.
4. Confirm **Open**, then drag `metacodex.app` into `/Applications`.

This is the override flow documented by [Apple Support](https://support.apple.com/102445).

### Terminal fallback

Verify the file before removing quarantine:

| Mac | File | Expected SHA-256 |
| --- | --- | --- |
| Apple Silicon | `metacodex_1.0.0_aarch64.dmg` | `859521bc39f023768c244d00cac9135a34eb42474715b7e15e328839819ff5f6` |
| Intel | `metacodex_1.0.0_x64.dmg` | `fdbd4154754d36859f72a5f024e7b498575f1bf52747a15a4e10d90e001b0fc4` |

```bash
shasum -a 256 "$HOME/Downloads/metacodex_1.0.0_aarch64.dmg"
xattr -d com.apple.quarantine "$HOME/Downloads/metacodex_1.0.0_aarch64.dmg"
open "$HOME/Downloads/metacodex_1.0.0_aarch64.dmg"
```

Intel users should replace `aarch64` with `x64`. If Gatekeeper also blocks the app after it has been copied, run:

```bash
sudo xattr -dr com.apple.quarantine "/Applications/metacodex.app"
open "/Applications/metacodex.app"
```

These commands remove quarantine only from the specified metacodex file. They do not disable Gatekeeper system-wide. A future release signed with an Apple Developer ID and notarized by Apple will remove this extra step.

## Upgrading from 0.0.19

The app keeps the same `com.metacodex.app` identity and `~/.metacodex` configuration root, so existing projects, settings, keybindings and workspace state continue forward. Startup compatibility archives state from the removed Agent view and remote SSH experiment under `state/legacy-agent/` and `state/legacy-ssh/`.

The previous product remains available as [Legacy v0.0.19](https://github.com/victorbenazzi/metacodex/releases/tag/v0.0.19), with its source frozen on the [`legacy/v0`](https://github.com/victorbenazzi/metacodex/tree/legacy/v0) branch.
